# Read-only research reliability

Phase #5 tasks: “Monitor scheduled GitHub Actions failures”, “Last successful data refresh indicator”, and “Stale or missing data alerts”. This evidence concerns historical research and simulated paper records, never profitability or real execution.

Run `python -m monitoring.health` with the standard Actions `GITHUB_REPOSITORY` and `GH_TOKEN` environment variables, or supply `--actions-json evidence.json` for offline normalized workflow evidence. No additional account credentials are needed. The CLI writes `work/monitoring/health.json` and `health.md` and exits 1 for attention, 0 for healthy. The dedicated daily/completion-triggered workflow publishes both as a 30-day artifact and a readable Actions summary. It has read-only repository/Actions permissions, checks out main, and never executes code or downloads artifacts from the triggering run.

Workflow paths are resolved to immutable workflow IDs. Runs are filtered to main and ordered by run number and attempt, not display name. Failure, cancellation, timeout, never-run, missing workflow, pending execution, API unknown, and success remain separate indicators. Last successful workflow time is execution evidence only; it never claims a market refresh. API failure produces unknown status, never success.

Source freshness uses CSV source sessions, not filesystem modification times, commit times, run completion times, or legacy `date_utc` run labels. JSON evidence records the last observed source session per symbol and a content hash. Legacy paper files without `price_session`, invalid prices, unfinished crypto days, and NO_DATA records fail closed. Stock history uses the oldest of each symbol's latest observations. Mixed strategy comparisons use stock or crypto rules per symbol. A successful run with old or all-missing comparison data cannot refresh these indicators. Output checks independently flag missing, zero-byte, header-only CSV, or invalid JSON files. Presence alone does not validate research conclusions or prove a refresh.

Stock freshness expects the latest regular US equity session after a conservative 23:00 UTC publication grace, including weekends and regular exchange holidays. Early closes use the same conservative grace. Crypto expects yesterday's completed UTC day, every day. This provisional calendar does not cover exceptional exchange closures; the immutable dataset/session contract proposed in next-round task 2 remains an integration dependency. Current paper and historical outputs do not yet supply complete provenance or expected-symbol manifests. Missing symbols omitted entirely from a dataset cannot be inferred; header-only research outputs intentionally remain attention even when a producer treats no observations as normal. ETF monthly series and undated research reports receive presence checks only, not invented daily freshness claims.

Alerts have stable `category:path` keys and state values. `--previous health.json` computes new/changed and recovered alerts deterministically; unchanged alerts are suppressed from that transition list. Every report still contains all current alerts. Scheduled jobs are stateless and intentionally publish a full snapshot each run; they do not restore prior artifacts, send notifications, open issues, or claim cross-run notification deduplication. Saved artifacts supply read-only evidence for comparison. No source data, strategy, roadmap checkbox, or issue state is modified.

Validation: `python -m unittest discover -s tests -v` and `python -m compileall -q paper_trader.py crypto_paper_trader.py strategy_comparison.py monitoring`. Tests cover workflow failure/cancellation/retry recovery, pagination, source failure/recovery, weekend/holiday/grace boundaries, unfinished crypto days, missing source dates, all-missing/empty outputs, invalid prices, and alert transitions.

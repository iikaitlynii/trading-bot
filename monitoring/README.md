# Read-only research reliability

Phase #5 tasks: “Monitor scheduled GitHub Actions failures”, “Last successful data refresh indicator”, and “Stale or missing data alerts”. This evidence concerns historical research and simulated paper records, never profitability or real execution.

Run `python -m monitoring.health` with the standard Actions `GITHUB_REPOSITORY` and `GH_TOKEN` environment variables, or supply `--actions-json evidence.json` for offline normalized workflow evidence. No additional account credentials are needed. The CLI writes `work/monitoring/health.json` and `health.md` and exits 1 for attention, 0 when all configured checks pass. The daily/completion-triggered workflow publishes both as a 30-day artifact and a readable Actions summary, including on failure. It has read-only repository/Actions permissions, checks out main, and never executes code or downloads artifacts from the triggering run. The new scheduled workflow becomes active on the default branch after human-reviewed integration; PR CI exercises its CLI with deterministic fixtures.

Workflow paths resolve to immutable workflow IDs. Runs are filtered to main and ordered by run number and attempt, not display name. Failure, cancellation, timeout, never-run, missing workflow, pending execution, API unknown, and success remain separate indicators. Last successful workflow time is execution evidence only; it never claims a market refresh. API failure produces unknown status, never success.

Source freshness uses CSV source sessions, not filesystem modification times, commit times, run completion times, or legacy `date_utc` run labels. JSON evidence records last observed source sessions, content hashes, missing/unexpected symbols, and validation issue codes. Each price stream requires a close column and finite positive prices; comparisons instead require positive session counts, and shadow research requires finite account values. Negative performance is not a stale-data signal. Blank symbols, malformed rows, duplicate columns, duplicate symbol/session keys, and duplicate snapshot symbols fail closed. Identical duplicates are also ambiguous and rejected; historical series can contain distinct sessions per symbol. Explicit independent manifests list the full requested universe for each producer, including lab universe/variant pairs. AST-based regressions prevent those manifests from drifting from producer configuration. Unknown output paths require an explicit universe and otherwise return `UNKNOWN_COVERAGE`, never FRESH.

`NO_DATA` is an availability state independent of price parsing. A record with NO_DATA never counts as a successful source observation, including when close or price_session is absent or when a price is supplied. Legacy stock/crypto files without an explicit source date remain invalid until a producer writes a genuine new snapshot; no run-date fallback or historical rewrite occurs. The stock producer now adds `price_session` from the actual returned close series, preserving its legacy date field and all existing simulated trading decisions.

Monitoring adopts the shared `data_contracts.sessions` calendar from PR #15. XNYS coverage is bounded to 2024–2027, with regular holidays, the January 9, 2025 Carter mourning closure, published early closes, and DST-aware close times. Unsupported calendar dates fail closed. At an exact session close the stock session is completed; there is no extra publication grace. Crypto uses completed UTC days, including weekends. Stock history and forward shadow records use each expected member's latest source session; mixed comparisons apply the appropriate stock or crypto calendar per asset. Freshness also covers historical shadow snapshots and true forward shadow CSVs. Missing, empty, header-only, invalid, or stale results remain attention even after a successful workflow. Real producers may legitimately have no observations; that is reported honestly as unavailable rather than successful research.

Scope limits: this monitor validates latest-session availability, declared coverage and record shape, not every historical interior session, provider authenticity, corporate actions, benchmark eligibility, or profitability. It reuses the calendar without claiming legacy CSVs satisfy the full immutable snapshot/provenance contract. Old out-of-range historical rows require reviewed calendar coverage. ETF monthly series, undated reports, and other outputs outside `SOURCES` receive presence/JSON-parsing checks only; PRESENT is not a freshness claim. Future unexpected exchange closures require a reviewed calendar update. Missing scheduled runs are not inferred from cron deadlines; latest known run state and source freshness are separate evidence.

Alerts have stable `category:path` keys and state values. `--previous health.json` computes new/changed and recovered alerts deterministically; unchanged alerts are suppressed from that transition list. Every report still contains all current alerts. Scheduled jobs are stateless and intentionally publish a full snapshot each run; they do not restore prior artifacts, send notifications, open issues, or claim cross-run notification deduplication. Saved artifacts supply read-only evidence for comparison. The monitor does not modify source data, strategies, roadmap checkboxes, or issue state.

Validation: `python -m unittest discover -s tests -v` and `python -m compileall -q paper_trader.py crypto_paper_trader.py strategy_comparison.py monitoring data_contracts`. Deterministic tests cover each integration review finding, stock producer/monitor compatibility, shared calendar boundaries, workflow/API failure, missing/stale research CLI exit codes and evidence, healthy recovery, manifests, and CI path/compilation coverage. All fixtures are synthetic illustrative data, not market downloads or profitability evidence. The full suite also exercises merged PRs #13, #15 and #16.

## Contract and publication

`data_contracts/ingestion.py` archives exact HTTP response bytes under SHA-256 names, including rejected HTTP responses. Every accepted symbol gets PR #15's immutable close snapshot: exact symbol/endpoint, retrieval/as-of clocks, raw-close basis, coverage, session calendar, Python version and source commit. HLCV exports retain provider precision; null/nonfinite prices or volume, invalid ranges, negative/fractional volume, duplicate/gapped/invalid sessions, stale endpoints and insufficient completed history block acceptance. Reported zero volume is retained as reported, not synthesized; stricter volume consumers must reject it themselves.

All four requested symbols must validate before a content-addressed export and bundle are created. A same-filesystem atomic pointer swap accepts the complete bundle. A failed swap preserves the old pointer. Orphan immutable evidence is safe to retain. Future/current unfinished observations remain in raw evidence but are excluded from completed snapshots. Calendar support remains bounded to 2024–2027 and fails closed beyond it.

Scheduled stock/crypto paper getters read the frozen bundle via `MARKET_DATA_MANIFEST`, check bundle/raw/snapshot hashes, exact universe/symbol identity, shared as-of and latest completed session before returning prices. No download fallback occurs when that variable is set. Stock paper completion uses the shared calendar, including early close/DST/holidays. Signal rules, fill timing, costs and saved accounts are unchanged. Crypto requests two years rather than one to archive more available evidence; the same 100-session warmup and trailing strategy windows apply.

Stock-history publishes the legacy column-compatible CSV only after full validation; immutable bundle/export is authoritative. The CSV and pointer are separate local replacements; a crash between them can leave the old compatibility CSV, but the collector fails and the workflow does not commit it. Existing CSV remains on any validation failure.

Three ingestion workflows share a concurrency group, rebase before push, fail visibly on publication errors, and always upload diagnostic JSON plus provider evidence. `ACCEPTED`, `NO_NEW_DATA`, `BLOCKED`, per-symbol reasons, source sessions and local publication state are explicit. The Actions artifact separately records the overall job/publication outcome: `LOCAL_ACCEPTED` is never a claim of a successful remote push. Other producer workflows do not share this lock; cross-workflow conflicts still fail visibly. GitHub scheduling is best effort; artifacts expose delay without guaranteeing a dispatch SLA. Existing research-health failures and alerts remain unchanged.

Two independently reproduced defects were corrected on the existing branch:

- `accepted_close` did not check the linked HLCV export hash. A modified export was accepted while close snapshots still validated. It now rejects `EXPORT_HASH_MISMATCH`; the legacy stock exporter performs the same check before replacing the CSV.
- `atomic` shared one fixed `.tmp` filename among concurrent writers. A deterministic interleaving caused one writer to consume the other's staging file and the other writer to fail. Each write now owns a unique same-directory staging file. Replacement remains atomic; concurrent completion order determines the accepted complete payload. This is atomic visibility, not a power-loss durability guarantee or an all-files transaction.
